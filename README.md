# בוט חיפוש משרות סטודנט בלינקדאין

בוט שמנטר את שני חיפושי המשרות של אלון בלינקדאין (סטודנט באנגלית ובעברית, ישראל, 24 שעות אחרונות) ושולח התראת טלגרם על כל משרה חדשה, כדי להגיש קורות חיים מוקדם ככל האפשר.

הכל חינמי: GitHub Actions מריץ את הבדיקה כל 15 דקות, בלי שרת ובלי שהמחשב יהיה דלוק. נגד פספוסים, כל בדיקה סורקת כל חיפוש בשתי גישות מצטלבות (מיון לפי תאריך + מיון לפי רלוונטיות) ומאחדת את התוצאות.

## איך זה עובד

נקודה חשובה להבנה: לינקדאין מציגה חיפוש עם מרכאות בהתאמה מדויקת רק למשתמש מחובר. לגולש לא מחובר (וגם לבוט) היא מגישה גרסה מורחבת של אותו חיפוש, מרופדת ב"משרות דומות" שלא באמת מכילות את מילת החיפוש. לכן הבוט עובד בשני שלבים: שליפת הפיד הציבורי (שהוא קבוצת-על של החיפוש האמיתי), ואז שחזור הסינון המדויק אצלנו. כך מקבלים בדיוק את מה שמציג החיפוש המחובר, בלי לסכן את חשבון הלינקדאין בהרצת אוטומציה מחוברת.

1. `watcher.py` שולף את תוצאות החיפוש דרך ממשק האורחים הציבורי של לינקדאין. ללא התחברות וללא ספריות חיצוניות, Python סטנדרטי בלבד.
2. החיפושים מוגדרים ב-`config.json` עם מיון לפי תאריך (sortBy=DD), כך שמשרה חדשה תמיד מופיעה בעמוד הראשון.
3. מזהי משרות שכבר נראו נשמרים ב-`state/seen_jobs.json` (נשמר בחזרה לריפו אחרי כל סבב). משרה שלא הופיעה שם היא מועמדת חדשה.
4. כל מועמדת עוברת שני מסננים שמשחזרים את החיפוש המדויק:
   - מיקום: חייב להכיל "Israel" או "ישראל" (מסנן את הרעש שלינקדאין מדליפה מחו"ל).
   - מילה מדויקת: `match_word` של אחד החיפושים ("student" או "סטודנט") חייבת להופיע כמילה שלמה בכותרת המשרה. "סטודנטים" או "students" לא נחשבים, בדיוק כמו בהתאמת מרכאות של לינקדאין (כויל מול התצוגה המחוברת של אלון: התאמת המרכאות שלה עובדת לפי כותרת). אפשר להרחיב חיפוש גם לתיאור המלא עם `"match_in": ["title", "description"]`, ואז נשלף התיאור בבקשה נוספת פר משרה.
5. רק משרה שעברה את שני המסננים נשלחת לטלגרם. משרה שנפסלה נרשמת בלוג ומסומנת כמוכרת כדי לא להיבדק שוב.
6. ברגע שעמוד שלם מכיל רק משרות מוכרות, הסריקה נעצרת. בסבב שגרתי זו בקשה אחת או שתיים לכל חיפוש ועוד תיאור בודד פה ושם, עומס מינימלי על לינקדאין.
7. אם יש יותר מ-12 משרות חדשות בסבב, הן נשלחות כרשימות מרוכזות במקום הודעה לכל משרה.

## הקמה (פעם אחת, בערך 5 דקות)

### שלב 1: יצירת בוט טלגרם

1. בטלגרם, פתחו צ'אט עם `@BotFather`.
2. שלחו `/newbot`, בחרו שם (למשל "משרות סטודנט") ושם משתמש שמסתיים ב-bot.
3. שמרו את הטוקן שמתקבל (נראה כמו `123456789:AAE...`).
4. פתחו צ'אט עם הבוט החדש ולחצו Start (בלי זה הבוט לא יכול לשלוח לכם הודעות).
5. כדי לקבל את מזהה הצ'אט: גלשו בדפדפן אל
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
   (החליפו `<TOKEN>` בטוקן), וחפשו בתשובה את `"chat":{"id":123456789`. המספר הזה הוא ה-chat id.

### שלב 2: ריפו בגיטהאב וסודות

1. צרו ריפו בגיטהאב ודחפו אליו את התיקייה הזו (או בקשו מקלוד לעשות זאת).
   - ריפו ציבורי: דקות Actions ללא הגבלה, אפשר כל 15 דקות.
   - ריפו פרטי: 2000 דקות חינם בחודש, שנו את ה-cron ל-`7,37 * * * *` (כל 30 דקות).
2. בריפו: Settings > Secrets and variables > Actions > New repository secret:
   - `TELEGRAM_BOT_TOKEN` = הטוקן מ-BotFather
   - `TELEGRAM_CHAT_ID` = מזהה הצ'אט
3. בלשונית Actions: אשרו הפעלת workflows אם גיטהאב מבקש.

### שלב 3: בדיקה

בלשונית Actions בחרו את `watch-jobs` ולחצו Run workflow. תוך דקה אמורות להגיע הודעות טלגרם על המשרות שנוספו מאז עדכון ה-state האחרון.

## הרצה מקומית (אופציונלי)

```powershell
$env:TELEGRAM_BOT_TOKEN = "..."
$env:TELEGRAM_CHAT_ID = "..."
python watcher.py
```

בלי משתני הסביבה הסקריפט רץ במצב dry-run ורק מדפיס, בלי לשלוח.

תוכנית ב' אם GitHub Actions ייחסם על ידי לינקדאין (נדיר, אבל אפשרי): להריץ מקומית כל 5 דקות דרך Task Scheduler:

```powershell
schtasks /Create /SC MINUTE /MO 5 /TN "linkedin-job-watcher" /TR "python \"G:\projects\בוט חיפוש משרות\watcher.py\""
```

(במקרה כזה צריך להגדיר את משתני הסביבה ברמת המשתמש דרך `setx`, ולבטל את ה-workflow בענן כדי למנוע כפילויות.)

## כיוונון

- **תדירות**: שורת ה-cron ב-`.github/workflows/watch-jobs.yml`. שימו לב שגיטהאב לפעמים מאחר סבבים מתוזמנים בכמה דקות, בפועל הקצב הוא 15-25 דקות.
- **רשת הביטחון נגד פספוסים** בנויה משלוש שכבות: שתי גישות סריקה מצטלבות בכל בדיקה (הפיד הציבורי "מרצד" משרות, בעיקר ממומנות, וכל מיון מפספס אחרות); חלון של 24 שעות אחורה בכל בדיקה, כך שכל משרה מקבלת כ-96 הזדמנויות להיתפס לפני שהיא יוצאת מהחלון; ומשרה שמופיעה בשני החיפושים נבדקת מול שניהם.
- **מגבלה מובנית שכדאי להכיר**: קיימות משרות נדירות (נצפה מקרה אחד ביום הכיול, משרה ממומנת של KLA) שלינקדאין מגישה רק למשתמשים מחוברים, ואף בוט מבוסס גלישת אורח לא יכול לראות אותן. הכיסוי המשלים: להשאיר דלוקות את ההתראות המובנות של לינקדאין (מתג Set alert בשני דפי החיפוש). הן איטיות, אבל רואות את התצוגה המחוברת.
- **הוספת חיפוש**: מוסיפים אובייקט ל-`config.json` עם `label`, `match_word` (המילה שחייבת להופיע במשרה עצמה; בלעדיה הפיד הציבורי המורחב עובר כמו שהוא) ו-`params` (את הפרמטרים לוקחים מכתובת ה-URL של חיפוש בלינקדאין: keywords, geoId, location, f_TPR).
- **חלון הזמן**: `f_TPR=r86400` פירושו 24 שעות אחרונות. לא לצמצם, החלון הרחב מגן מפני החמצות אם היו כמה סבבים כושלים ברצף.
- **עומק הסריקה**: `MAX_RESULTS_PER_SEARCH` ב-`watcher.py` (כרגע 30). בכל סבב נבחנות רק 30 המשרות החדשות ביותר בכל חיפוש; בזכות המיון לפי תאריך זה מכסה הרבה יותר מרבע שעה של פרסומים, ושומר על סבבים קצרים.
- **סף הרשימות המרוכזות**: `DIGEST_THRESHOLD` ב-`watcher.py`.
- **מסנן מיקום**: `filters.location_must_contain` ב-`config.json`. לינקדאין מדי פעם מדליפה לתוצאות משרות מחוץ לישראל; משרה שהמיקום שלה לא מכיל אחד מהמונחים נזרקת (ונרשמת בלוג).

## שכבה משלימה אופציונלית: גשר מיילי ההתראות (extras/gmail_bridge.gs)

חלק מהמשרות הממומנות/המחודשות מוצגות רק למשתמשים מחוברים ולכן בלתי נראות לבוט (נצפו 3 מקרים ביום ההקמה). מיילי ההתראה המובנים של לינקדאין כן מכילים אותן. הסקריפט `extras/gmail_bridge.gs` רץ ב-Google Apps Script (חינם, בתוך חשבון הגוגל שמקבל את המיילים), קורא את מיילי ההתראות כל 10 דקות, מדלג על כל משרה שהבוט כבר שלח (בדיקה מול קובץ ה-state הציבורי בריפו), ושולח לטלגרם רק את החדשות באמת. הוראות התקנה בראש הקובץ. את הטוקן של הבוט ממלאים בתוך הסקריפט, לעולם לא בריפו.

## תקלות נפוצות

- **סבב אדום בגלל 429 או timeout**: לינקדאין חסם זמנית. הסקריפט מנסה שוב 4 פעמים עם השהיות; אם נכשל, הסבב הבא (בעוד רבע שעה) משלים את הפער. חלון ה-24 שעות מבטיח שכלום לא הולך לאיבוד.
- **גיטהאב השבית את התזמון**: אחרי 60 יום בלי פעילות בריפו גיטהאב מכבה workflows מתוזמנים ושולח מייל. קומיטי ה-state השוטפים בדרך כלל מונעים זאת; אם קרה, כפתור Enable בלשונית Actions מחזיר לחיים.
- **לא מגיעות הודעות**: לוודא שלחצתם Start בצ'אט עם הבוט, ושהסודות הוגדרו נכון (בדיקה ידנית: Run workflow ולקרוא את הלוג).

## הערה

הבוט משתמש בממשק ציבורי (ללא התחברות) בקצב מנומס של בקשות בודדות לרבע שעה. זה שקול לגלישה רגילה בדף החיפוש, אבל טכנית לינקדאין לא אוהבת אוטומציה, לכן הקצב שמור נמוך בכוונה. לא להוריד את ההשהיות ולא להריץ בתדירות גבוהה בהרבה.
